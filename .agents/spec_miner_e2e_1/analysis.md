## 1. 概要と分析目的

## 3. Edge Cases (発見されたエッジケース一覧)

仕様調査から判明した境界値、極端な入力、および異例な条件の一覧です。

| # | Feature | Input | Observed Behavior (期待される安全な挙動) |
|---|---------|-------|-----------------------------------------|
| E01 | 無限ループガード (F20) | `while True: pass` または 10,001 回以上の `for i in range(10001): pass` | 10,000ステップ目で `TraceLimitExceeded` エラーが捕捉され、UIに上限超過メッセージが表示され、画面がフリーズしない |
| E02 | NaN / Infinity サニタイズ (F21) | `x = float('nan')`, `y = float('inf')`, `z = float('-inf')` | Worker と UI 間の postMessage 通信で JSON 破綻を起こさず、変数履歴表に `"NaN"`, `"Infinity"`, `"-Infinity"` と表示される |
| E03 | 構文エラー (F22) | `if True` (コロン欠損) や `def foo(` などの SyntaxError コード | Pyodide 解析時にエラーが検知され、UI に「構文エラー: line X」が表示され、トレース実行が開始されない |
| E04 | ゼロ除算等の例外 (F22) | `x = 10 / 0` などの ZeroDivisionError コード | 例外発生行までのステップは保持され、例外発生行で「ZeroDivisionError: division by zero」が表示されステップ停止する |
| E05 | 空入力 / コメントのみ (F03, F06) | 完全な空文字 `""` または `# こちらはコメントです` のみ | トレースステップ数が 0 となり、エラーを出さずに「実行可能なコードがありません」またはステップ0状態で留まる |
| E06 | 巨大変数 / 多重定義 (F12) | 100個以上の異なる変数を定義・代入するコード | 変数履歴表が水平スクロール可能となり、UI表示が崩れずパフォーマンスが維持される |
| E07 | 深い制御構造ネスト (F16, F17) | 10重以上にネストされた `if` / `for` / `while` 構造 | 流れ図が拡大・縮小・スクロール可能にレンダリングされ、ノードハイライトが正しく対応する |
| E08 | 巨大文字列 / 特殊文字 (F15) | 10,000文字の文字列 print 出力、または絵文字・改行・タグ文字 `<b>test</b>` | print 出力コンソールでテキストが適切にエスケープ/折り返し表示され、レイアウト崩れを起こさない |
| E09 | 高速ナビゲーション操作 (F07, F10) | 「次へ」ボタンのミリ秒単位超高速連続クリック、またはスライダーの連続激しいドラッグ | Worker 通信や UI 表示更新が追従し、非同期競合による表示不一致や状態破損が発生しない |
| E10 | 再帰関数呼出 (F14) | `def fact(n): return 1 if n<=1 else n*fact(n-1)` の再帰実行 | 関数の呼び出しごとにローカルスコープ `locals` が適切に識別・表示され、コールスタックからの復帰が追尾される |

| E12 | Pyodide 初期化中操作 (F01) | Pyodide ロード中（ネットワーク遅延時）に「次へ」ボタンやエディタ操作を試みる | ローディングオーバーレイによりすべての操作ボタンが非活性化(Disabled)され、ロード完了後に活性化する |

## 4. 4-Tier Framework に基づく E2E テスト要件仕様書

本節では、要求駆動ブラックボックステストを実施するための **4-Tier Framework** テストスイートの具現的ケース仕様を定義します。

---

### 4.1 Tier 1 — 機能網羅 (Feature Coverage)

各機能に対して**最低5ケース以上の正常系テスト**を策定します（全9カテゴリ、45ケース以上）。

#### Category 1: Pyodide 初期化 & レイアウト (F01, F02)
- **TC-T1-01-1**: アプリ起動時に Pyodide ローディングインジケータが表示されること
- **TC-T1-01-2**: Pyodide 初期化完了後にローディングが消え、メイン操作画面が表示されること
- **TC-T1-01-3**: ヘッダーに TraceApp のタイトルと教科書風デザインが表示されていること
- **TC-T1-01-4**: 左パネル（コード/流れ図）と右パネル（変数履歴/print出力）の2ペイン構成が正しく配置されていること
- **TC-T1-01-5**: 画面サイズ変更（レスポンシブ）時にもレイアウトが崩れないこと

#### Category 2: サンプルプログラム (F05)
- **TC-T1-02-1**: 初期状態でデフォルトサンプル（合計計算等）が Monaco Editor にロードされていること
- **TC-T1-02-2**: サンプルドロップダウンから「条件分岐」を選択するとエディタのコードが更新されること
- **TC-T1-02-3**: サンプルドロップダウンから「ループと関数」を選択するとエディタのコードが更新されること
- **TC-T1-02-4**: サンプル変更時に直前のトレース状態が自動的にリセットされること
- **TC-T1-02-5**: サンプルを順次切り替えてもエラーが発生せずコードが正しくロードされること

#### Category 3: コード入力 & ファイルアップロード (F03, F04)
- **TC-T1-03-1**: Monaco Editor に直接 Python コードを入力・編集できること
- **TC-T1-03-2**: Monaco Editor 内で Python のキーワード（def, if, for, return 等）がシンタックスハイライトされること
- **TC-T1-03-3**: 妥当な `.py` ファイルをアップロードすると、その内容が Monaco Editor にロードされること
- **TC-T1-03-4**: アップロードされたコードに対して即座にトレース実行が可能になること
- **TC-T1-03-5**: エディタでコードを追記・修正した際、既存の行構造が正しく保持されること

#### Category 4: ステップナビゲーション (F07, F08, F09, F10)
- **TC-T1-04-1**: 「次へ」ボタンを押すとステップが 1 進み、ステップ表示（例: `Step 1 / 4`）が更新されること
- **TC-T1-04-2**: 「前へ」ボタンを押すとステップが 1 戻り、ステップ表示が更新されること
- **TC-T1-04-3**: 「リセット」ボタンを押すとステップが 0（初期状態）に戻ること
- **TC-T1-04-4**: ステップスライダーをドラッグして中間ステップに移動できること
- **TC-T1-04-5**: 最終ステップに達した際、「次へ」ボタンが非活性（Disabled）状態になること

#### Category 5: エディタ実行行デコレーション (F11)
- **TC-T1-05-1**: ステップ 1 実行時、Python の 1 行目が Monaco Editor 上でハイライトされること
- **TC-T1-05-2**: 「次へ」を押すたびにハイライト行が現在実行行に追従して移動すること
- **TC-T1-05-3**: 条件分岐（if）で条件が成立したブロックの行にハイライトが移動すること
- **TC-T1-05-4**: 条件不成立の elif/else ブロックがスキップされてハイライトが移動すること
- **TC-T1-05-5**: ループ処理において、繰り返し実行される行にハイライトが繰り返し移動すること

#### Category 6: スプレッドシート型変数履歴表 (F12, F13, F14)
- **TC-T1-06-1**: 代入文が実行されたステップで、変数名と初期値が変数履歴表に表示されること
- **TC-T1-06-2**: 変数の値が更新されたステップで、該当するセルがハイライト表示されること
- **TC-T1-06-3**: 変数が更新された際、その変数名に対応する列全体がハイライト強調されること
- **TC-T1-06-4**: 基本データ型（int, float, str, bool）の値が正しく文字列としてセル内に表示されること
- **TC-T1-06-5**: 関数内実行時にローカル変数がグローバル変数と区別されて表示されること

#### Category 7: print 出力コンソール (F15)
- **TC-T1-07-1**: `print()` 文が実行される前はコンソール領域が空（または初期状態）であること
- **TC-T1-07-2**: `print("hello")` 実行ステップに到達すると、コンソールに "hello" が表示されること
- **TC-T1-07-3**: 複数回 `print()` が実行された場合、改行区切りで累積出力が表示されること
- **TC-T1-07-4**: 「前へ」ボタンで `print()` 実行前ステップに戻ると、コンソール出力も直前の状態に消去/後退すること
- **TC-T1-07-5**: 数値や計算結果の print 出力（`print(x + y)`）が正しい評価値として表示されること

#### Category 8: 流れ図レンダリング (F16, F17)
- **TC-T1-08-1**: 代入・処理コードが長方形 (Process) ノードとして流れ図に描画されること
- **TC-T1-08-2**: if 条件分岐コードがひし形 (Decision) ノードとして流れ図に描画されること
- **TC-T1-08-3**: for / while ループ構造が六角形 (Loop Start/End) ノードとして流れ図に描画されること
- **TC-T1-08-4**: 関数定義/呼び出しが二重線長方形 (Subroutine) ノードとして流れ図に描画されること
- **TC-T1-08-5**: 開始・終了が角丸長方形 (Terminal) ノードとして流れ図に描画されること

#### Category 9: 流れ図連動 & タブ切り替え (F18, F19)
- **TC-T1-09-1**: 「コード」タブから「流れ図」タブへ切り替えると SVG/Canvas 流れ図が表示されること
- **TC-T1-09-2**: 「流れ図」タブから「コード」タブへ切り替え返すと Monaco Editor が表示されること
- **TC-T1-09-3**: ステップ実行時、現在実行中の行に対応する流れ図ノードがハイライト表示されること
- **TC-T1-09-4**: 「流れ図」タブ表示中に「次へ」ボタンを押すと、アクティブノードが連動して切り替わること
- **TC-T1-09-5**: タブを何度往復切り替えしても、トレース位置とハイライト状態が維持されること

### 4.2 Tier 2 — 境界値・コーナーケース・異常系 (Boundary & Corner)

限界値、エッジケース、異常系の堅牢性を検証するケース群です。

- **TC-T2-01 [10,000ステップ上限超過]**:
  - *操作*: `i = 0; while i <= 10000: i += 1` などの 10,000 ステップを超えるコードを入力しトレース実行。
  - *検証*: `TraceLimitExceeded` ガードが作動し、UIに「ステップ実行数の上限(10,000)を超えました」等のエラーメッセージが表示され、ブラウザフリーズなしに安全停止すること。
- **TC-T2-02 [NaN / Infinity 特殊値サニタイズ]**:
  - *操作*: `a = float('nan'); b = float('inf'); c = float('-inf')` を実行。
  - *検証*: postMessage 通信エラーを起こさず、変数履歴表に `"NaN"`, `"Infinity"`, `"-Infinity"` と正しく表示されること。
- **TC-T2-03 [構文エラー SyntaxError]**:
  - *操作*: `def foo(` や `if x == 5` (コロン忘れ) の不完全コードを入力して実行。
  - *検証*: Pyodide AST / 実行時エラーが検出され、エディタ下部またはトーストに明確な構文エラーメッセージが表示されること。
- **TC-T2-04 [実行時例外 ZeroDivisionError]**:
  - *操作*: `x = 5; y = 0; z = x / y` を実行。
  - *検証*: `z` の計算行で実行が停止し、「ZeroDivisionError: division by zero」が表示され、直前のステップまでの変数履歴が保持されること。
- **TC-T2-05 [空入力・コメントのみ]**:
  - *操作*: 空文字、または `# comment only` のみのコードを実行。
  - *検証*: アプリがクラッシュせず、ステップ数 0 で安全に待機状態となること。
- **TC-T2-06 [大量変数表示]**:
  - *操作*: 50個以上の変数（`v1=1; v2=2; ... v50=50`）を定義・代入するコードを実行。
  - *検証*: 変数履歴表が崩れず、水平スクロールバーで全変数が正常に閲覧できること。
- **TC-T2-07 [深層ネスト構造]**:
  - *操作*: 8重の `if` および `for` ネストコードを入力・実行。
  - *検証*: AST 流れ図生成が破綻せず、縮小・スクロール可能な流れ図として描画されること。
- **TC-T2-08 [特殊文字・エスケープ print 出力]**:
  - *操作*: `print("Line1\nLine2\tTab <script>alert(1)</script>")` を実行。
  - *検証*: print コンソールで HTML タグがエスケープされ、安全かつ正しくテキスト表示されること。
- **TC-T2-09 [再帰関数トレース]**:
  - *操作*: `def count_down(n): return n if n<=1 else count_down(n-1)` を実行。
  - *検証*: 深さごとにローカル変数が正しく記録され、スタックフレームの呼び出しと復帰が可視化されること。
- **TC-T2-10 [Pyodide Worker 遅延・遮断保護]**:
  - *操作*: Pyodide ロード処理のシミュレーション中、操作ボタンを連続クリック。
  - *検証*: 全ナビゲーションボタンが非活性化されており、不正な命令送出が発生しないこと。

### 4.3 Tier 3 — 機能複合・相互作用 (Cross-Feature Combinations)

複数機能が同時に連動する高度な操作ペアを検証します。

- **TC-T3-01 [4点同時ステート同期検証]**:
  - *操作*: スライダーをステップ 0 からステップ 3 へ一気にドラッグ移動。
  - *検証*: (1) Monaco Editor の実行行ハイライト、(2) 変数履歴表のステップ3時点の値と強調セル、(3) print 出力コンソールのステップ3時点の累積ログ、(4) 流れ図の該当ノードハイライト、の 4 要素が完全に同一ステップの状態で整合して更新されること。
- **TC-T3-02 [前へ・次へによる双方向状態整合]**:
  - *操作*: 「次へ」を 3 回押した後、「前へ」を 2 回押し、再度「次へ」を 1 回押す。
  - *検証*: 変数履歴表のセルハイライトおよび print コンソールの表示内容が、常に表示中のステップ番号のデータと 100% 一致すること。
- **TC-T3-03 [タブ切り替え時のハイライト状態保持]**:
  - *操作*: コードタブでステップ 2 まで進行 → 流れ図タブに切り替え（ノードハイライト確認） → 「次へ」でステップ 3 へ進行 → コードタブに復帰。
  - *検証*: コードタブ復帰時に Monaco Editor の 3 行目が正しくハイライトされていること。
- **TC-T3-04 [サンプル切替 ＋ カスタム編集 ＋ リセット連動]**:
  - *操作*: サンプル 1 を選択 → Monaco でコードを追記 → ステップ進行 → 「リセット」クリック。
  - *検証*: 追記したカスタムコードは保持されたまま、トレース状態（ステップ0）のみがクリアされること。
- **TC-T3-05 [ファイルアップロード ＋ 即座スライダー操作]**:
  - *操作*: `.py` ファイルをアップロード後、事前トレース完了を確認し、スライダーで一気に最終ステップへ移動。
  - *検証*: ファイル内コードの全実行結果および最終 print 出力がコンソールに正しく表示されること。
- **TC-T3-06 [超高速ナビゲーション連打とWorker追従性]**:
  - *操作*: 「次へ」ボタンを 100ms 間隔で 10 回連続クリック。
  - *検証*: Web Worker 通信のキュー処理が正常に行われ、UIが途中で固まることなく最終到達ステップまで滑らかに更新されること。

### 4.4 Tier 4 — 実用アプリケーションシナリオ (Real-World Application Scenarios)

`ORIGINAL_REQUEST.md` に提示されている**3つの検証用テストプログラム**および総合実用シナリオです。

#### Scenario 1: 検証用テスト1 — 基本的な順次・代入
```python
x = 5
y = 3
total = x + y
print(total)
```
- **検証フロー**:
  1. 上記コードを Monaco Editor に読み込む（または初期サンプル1を選択）。
  2. ステップ 0: トレース開始前。変数表は空、printコンソールは空。
  3. ステップ 1 (Line 1 `x = 5`): Monaco 1行目ハイライト。変数表に `x = 5` 追加・ハイライト。
  4. ステップ 2 (Line 2 `y = 3`): Monaco 2行目ハイライト。変数表に `y = 3` 追加・ハイライト。
  5. ステップ 3 (Line 3 `total = x + y`): Monaco 3行目ハイライト。変数表に `total = 8` 追加・ハイライト。
  6. ステップ 4 (Line 4 `print(total)`): Monaco 4行目ハイライト。printコンソールに `8` が出力。
  7. 流れ図確認: 順次処理として 4 つの長方形 (Process) ノードが描画され、各ステップで対応する長方形がハイライトされること。

#### Scenario 2: 検証用テスト2 — 条件分岐
```python
score = 75
if score >= 80:
    grade = "A"
elif score >= 60:
    grade = "B"
else:
    grade = "C"
print(grade)
```
- **検証フロー**:
  1. 上記コードを読み込む。
  2. ステップ 1 (Line 1 `score = 75`): `score = 75` 記録。
  3. ステップ 2 (Line 2 `if score >= 80:`): 条件判定 (False)。流れ図のひし形ノード (Decision) がハイライト。
  4. ステップ 3 (Line 4 `elif score >= 60:`): 条件判定 (True)。ひし形ノードがハイライト。
  5. ステップ 4 (Line 5 `grade = "B"`): `grade = "B"` 記録。
  6. ステップ 5 (Line 8 `print(grade)`): printコンソールに `"B"` が出力。`grade = "A"` や `"C"` の行はスキップされること。

#### Scenario 3: 検証用テスト3 — ループと関数
```python
def add(a, b):
    result = a + b
    return result

total = 0
for i in range(1, 4):
    total = add(total, i)
print(total)
```
- **検証フロー**:
  1. 上記コードを読み込む。
  2. ステップ 1 (Line 1 `def add...`): 関数定義ノード通過。
  3. ステップ 2 (Line 5 `total = 0`): `total = 0` 記録。
  4. ループ実行パス追尾:
     - `i = 1`: `add(0, 1)` 呼出 → ローカルスコープ (`a=0, b=1, result=1`) → `total = 1`
     - `i = 2`: `add(1, 2)` 呼出 → ローカルスコープ (`a=1, b=2, result=3`) → `total = 3`
     - `i = 3`: `add(3, 3)` 呼出 → ローカルスコープ (`a=3, b=3, result=6`) → `total = 6`
  5. ループ終了後 (Line 8 `print(total)`): printコンソールに `6` が出力される。
  6. 流れ図確認: 二重線長方形 (Subroutine `add`) と 六角形 (Loop `for i in range`) が正しくノード描画され、ループ回数に応じてハイライトが循環すること。

#### Scenario 4: 総合学習体験シナリオ (デバッグ＆トレース操作)
- **ストーリー**: ユーザーが自分で書いた計算プログラムをアップロードし、スライダーで戻ったり進んだりしながら変数変化をチェックしてデバッグを行う演習。
- **検証フロー**:
  1. `.py` ファイルをアップロード。
  2. スライダーで中央のステップに一気にジャンプし、変数履歴表の値を観察。
  3. 「前へ」ボタンで変数が誤った値になった直前のステップを特定。
  4. Monaco Editor でコードを直接修正。
  5. 「リセット」から再度ステップ実行を行い、正しく修正された挙動（最終 print 出力）を確認。

## 5. 受入基準 (Acceptance Criteria) チェックリスト

`ORIGINAL_REQUEST.md` および `PROJECT.md` の受入基準をブラックボックステスト観点にマッピングしたチェックリストです。

### トレース実行 & UI連動
- [ ] サンプルプログラム（最低3種類）で「次へ」ボタンを押すとステップが進み、Monaco Editor上の対応する行がハイライトされる
- [ ] 「前へ」ボタンで前のステップに戻り、変数履歴表およびprint出力の表示も正しく戻る
- [ ] 「リセット」ボタンでトレース状態が初期化され、コード編集状態に戻る
- [ ] ステップスライダーのドラッグで任意のステップにジャンプでき、全UI表示が正しく更新される
- [ ] 各ステップで変更された変数のセルと列がハイライト表示される
- [ ] print()の出力が右パネル下部にステップ進行に応じて表示される
- [ ] 10,000ステップを超えるプログラムでエラーメッセージが表示され、ブラウザがフリーズしない
- [ ] Pyodideの初期化中はローディング表示が出て、完了後に操作可能になる

### Web Worker & 非同期処理
- [ ] Pyodideの初期化と実行がWeb Worker上で行われ、UI操作（ボタンクリック、テキスト入力等）がブロックされない
- [ ] Worker内でのトレース実行結果がメインスレッドに正しく返却され、UIと完全同期する

### 流れ図 (Flowchart)
- [ ] Pythonコードから流れ図が自動生成され、表示される
- [ ] 処理=長方形、判断=ひし形、ループ=六角形、関数=二重線長方形、端子=角丸長方形で正しく描画される
- [ ] ステップ実行時に流れ図の対応ノードがハイライトされる
- [ ] コードタブと流れ図タブの切り替えが正常に動作し、トレース状態が保持される

### コード入力 & ファイル
- [ ] Monaco Editorで Pythonコードを入力・編集できる
- [ ] .pyファイルをアップロードしてコードを読み込める
- [ ] ドロップダウンからサンプルプログラムを選択して切り替えられる
